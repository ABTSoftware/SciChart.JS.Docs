# The Parallel Coordinate Plot Type

The **Parallel Coordinate Plot** (PCP) is a way to visualize multivariate data — datasets where every record has many dimensions. One vertical axis is drawn per dimension, and each record becomes a polyline crossing every axis at its own value, which makes correlations, clusters and outliers between the dimensions easy to spot.

This chart type is not a single series. It is a composition of standard SciChart.js building blocks: one inner [`NumericAxis`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/numericaxis.html) per dimension positioned by a custom layout strategy, one [`FastLineRenderableSeries`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/fastlinerenderableseries.html) per record, and a set of [custom chart modifiers](/2d-charts/chart-modifier-api/custom-modifiers/custom-modifiers-overview/) for the interactions.

## How It Works

Unlike typical charts where one renderable series maps to one dataset, a Parallel Coordinate Plot is generated by **iterating over the records** of a multivariate dataset and creating a renderable series for **each record**.

- Every dimension (category) gets its own vertical `NumericAxis`, created with `isInnerAxis: true` and `axisAlignment: EAxisAlignment.Left`.
- A custom `LayoutStrategy` places dimension axis `i` at X data value `i`, so N axes are drawn at `x = 0, 1, ..., N-1` inside the series area.
- Every record becomes one polyline: `x` is the dimension index, `y` is the record's value for that dimension.
- Because each dimension has its own scale (mpg is ~10-45, weight is ~1400-6000), the values cannot share a Y axis. Instead each value is **normalized into 0..1** and drawn against a single **hidden** `NumericAxis`, while the visible per-dimension axes only supply the ticks and labels.
- When the hidden axis is zoomed or panned, each visible dimension axis derives its own `visibleRange` back from it, so the ticks stay aligned with the lines.
- Point metadata carries the original (pre-normalization) value, so tooltips can show real data rather than the 0..1 coordinate.

## Building a Parallel Coordinate Plot

Once the data source is configured, only the data decides how complex the chart is — add one category per dimension, set the per-record styling and call `build()`:


<LiveDocSnippet name="./Basic/demo" htmlPath="./Basic/demo.html" cssPath="./Basic/demo.css" />

In the code above:

- `ParallelCoordinateDataSource` owns the whole plot. `addCategory(name, values, axisType)` adds one dimension — pass `EAxisType.NumericAxis` for numbers and `EAxisType.CategoryAxis` for string values such as `origin`, which are mapped to the index of their unique value.
- `createSeriesFn(index)` returns the options for the record at `index`, so each polyline is coloured by its origin. Setting `interpolationPoints` above zero switches a record from a `FastLineRenderableSeries` to a `SplineLineRenderableSeries` for smooth curves.
- `onSelectedChanged` / `onHoveredChanged` make the hovered or clicked record thicker and fully opaque, driven by the built-in [`SeriesSelectionModifier`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/seriesselectionmodifier.html).
- `build()` creates the axes, the `XyDataSeries` and the renderable series. Call it again (or `moveCategory()`) to rebuild after changing the data or dimension order.
- All the zoom/pan modifiers are constrained to `EXyDirection.XDirection`, since all vertical geometry belongs to the hidden Y axis. `ZoomExtentsModifier` is restricted to that same hidden axis with `includedYAxisIds`.
- Range highlight, axis reorder, rubber-band zoom and pan all use the left-drag gesture, so the toolbar enables exactly one at a time.

What each piece does:

- **ParallelCoordinateDataSource** — the core. Holds the categories, creates the hidden coordinate axis plus one visible axis per dimension, normalizes every value into the hidden axis' 0..1 space and builds one `XyDataSeries` + renderable series per record. `moveCategory()` reorders dimensions and rebuilds in place; `getRecordIndexesInRange()` is the hit-test used by range highlighting.
- **ParallelCoordinatesInnerAxisLayoutStrategy** — extends [`LeftAlignedInnerAxisLayoutStrategy`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/leftalignedinneraxislayoutstrategy.html) and is assigned to `layoutManager.leftInnerAxesLayoutStrategy`. It gives every inner axis its own position on the X axis instead of stacking them, and splits each axis' `viewRect` so the title sits left of the axis line and the labels sit right of it.
- **ParallelCoordinateHighlightPaletteProvider** — an [`IStrokePaletteProvider`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/interfaces/istrokepaletteprovider.html) attached to each record series while a highlight is active. It bakes the dimmed / highlighted opacity into the stroke's alpha channel and is `isRangeIndependant`, so it does not re-run on zoom or pan.
- **ParallelCoordinatePlotHighlightModifier** — extends [`RubberBandXyZoomModifier`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/rubberbandxyzoommodifier.html) but overrides `performZoom` to highlight instead of zoom. The dragged X extent picks the dimension axis, the Y extent is converted through that axis' own coordinate calculator into a raw value range, and every record is paletted as highlighted or dimmed. A click clears it.
- **ParallelCoordinateAxisReorderModifier** — a [`CustomChartModifier2D`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/customchartmodifier2d.html) that grabs the nearest dimension axis on mouse-down, draws a dashed SVG drop indicator while dragging and calls `moveCategory()` once on release.
- **ParallelCoordinateCursorModifier** — a [`CursorModifier`:blue_book:](https://www.scichart.com/documentation/js/v5/typedoc/classes/cursormodifier.html) that also draws an SVG circle over the hit-tested vertex the tooltip is describing.
- **tooltipDataTemplate** — because every record is its own series, the default cursor tooltip would list all of them. This template picks the single closest record and prints every dimension's value for it, read from the point metadata.

## Scaling to Large Datasets

The demo above draws 100 records as 100 renderable series, which keeps per-record styling, hover and click selection cheap and simple. For much larger datasets, all records can instead be concatenated into a **single** `XyDataSeries` separated by `NaN` gap points, so the whole plot becomes one draw call. Per-record colour is then supplied by a `PaletteProvider` rather than by per-series strokes, and selection is done by hit-testing the record index instead of the series.

The [Parallel Coordinates example](https://www.scichart.com/demo/react/parallel-coordinates-chart) in the SciChart.js Demo shows both modes side by side, with 100,000 records in single-series mode.
